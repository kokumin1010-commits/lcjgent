# 店铺商品 A4 产品手卡 PDF 设计

## 目的与范围

每个店铺商品都可以从“商品与售后”列表直接打开A4产品手卡。用户明确要求使用已经制作完成的PDF，而不是在系统里重新填写或重排内容。因此功能以**普通版PDF与镜像版PDF分别上传**为主，打开手卡后直接预览原PDF，并支持浏览器打印、下载、替换和明确删除。

## 文件契约

| 字段 | 规则 | 用途 |
|---|---|---|
| `productId` | 正整数 | PDF只绑定到一个店铺商品 |
| `variant` | `normal`或`mirror` | 区分普通版与镜像版 |
| `storageKey` | 服务端生成 | 对象存储中的正式文件键，客户端不能伪造 |
| `fileName` | 255字符以内 | 显示原文件名 |
| `fileSize` | 1字节至20MB | 控制上传与预览负载 |
| `sha256` | 64位小写十六进制 | 文件真实性与重复校验 |
| `pageCount` | 1至20页 | 防止异常或过大文档 |
| `isA4` | `true`／`false`／`null` | 可识别时显示A4检查结果，不能识别时不伪报 |
| `uploadedAt`、`uploadedByName` | 服务端写入 | 审计上传时间和操作人 |

## 安全验证

上传端点沿用登录认证，只接受PDF。服务器不信任扩展名或浏览器MIME，而是检查`%PDF-`文件头、`%%EOF`文件尾、20MB上限、可确认页数和SHA-256。对象存储键由服务器生成；上传完成后才在数据库中登记。结构化手卡保存API不能自行提交任意对象键。

预览时数据库只保存对象键和元数据，API通过项目对象存储生成短期受控URL。替换PDF后清理旧对象；删除必须由用户明确点击，并写入商品审计日志。上传、种子登记和删除动作分别记录为`handcard_pdf_uploaded`、`handcard_pdf_seeded`和`handcard_pdf_removed`。

## 普通版与镜像版

普通版与镜像版是两个独立PDF，不再由网页CSS临时翻转生成。这样可以原样保留用户已经完成的KT板排版、文字、图片、页序和镜像方向。一个版本未登记时，只对该版本显示“未登记”，不会复制另一版本代替。

## Dr.Alba首批登记

用户提供的两份PDF均为3页A4：普通版SHA-256为`b0f63bc6690290715da43a2b288a8187051cf30b4ff0148cea2b387b80db5763`，镜像版SHA-256为`3ed27180787431ff484d70a470208d2921714d2f548b8c0f376666dde8d558a5`。系统只对平台商品ID`1735202677797193331`（或同一精确商品名）执行一次性登记，并在复制到项目正式对象存储前再次验证大小、SHA和3页A4条件。不会解析或改写PDF里的商品功效、成分、试验和专利内容。

## 现有数据保护

PDF功能继续复用独立的`store_product_handcards`表，不修改原商品、SKU、库存、价格、图片、推广活动或选品中心数据。原先已保存的结构化手卡内容保留在JSON中，但新界面不再要求重新填写；PDF上传与删除只更新对应的`normalPdf`或`mirrorPdf`元数据。
