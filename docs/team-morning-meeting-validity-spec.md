# 中日团队早会录音有效性规范

**制定日期：** 2026-08-27  
**适用页面：** `/morning-meeting`

## 目标

团队早会从“全公司每日一场”升级为**中国团队、日本团队每日各一场**。每场记录必须保留实际开始时间，录音过短时不得显示为“完成”，同时保留历史原始录音作为审计证据。

## 核心口径

| 项目 | 规则 |
|---|---|
| 团队 | `china`（中国团队）与 `japan`（日本团队） |
| 唯一场次 | 每个JST自然日、每个团队最多一条当前团队早会记录 |
| 参加者 | 仅允许选择对应国家/团队的在职员工；国家为空的员工不自动归入任一团队 |
| 开始时间 | 点击录音开始时在浏览器记录时间，服务端同时记录接收时间；展示到`HH:mm`，底层保存完整时间戳 |
| 最低有效时长 | 初始为60秒；管理员可在30–1,800秒之间调整 |
| 完成判定 | `status=completed`且`durationSeconds >= minimumDurationSeconds`才是有效完成 |
| 过短历史 | 不删除、不改写音频；在查询层显示“时长不足/无效”，不计入完成率、统计或昨日已录 |
| 重新录制 | 过短或失败记录可由原主持人或管理员重新录制；复用团队当日记录并保留审计时间字段 |
| 旧数据 | 原有无团队字段的`daily_team`记录标为`legacy`，继续在历史中显示，但不代替中国或日本团队当天完成状态 |

## 权限

管理员可以主持中国或日本团队早会、调整最低时长并查看全部历史。普通员工仅可主持自己所属团队的当日早会；不能跨团队选择参加者，也不能补录非当天场次。

## 界面

页面保留现有样式，在“团队早会”区域横向或纵向显示中国、日本两张卡。每张卡独立显示待完成、录音中、处理中、完成、时长不足或失败状态；录音时只显示该团队成员选择器。完成卡和历史列表显示团队、日期、开始时间、时长、主持人、参加人数和有效性。

## 验证边界

服务端必须拒绝低于当前最低时长的新录音，即使绕过前端直接调用接口也不能完成。60秒阈值下，59秒失败、60秒通过；历史3秒和11秒完成记录显示为无效。中国团队完成不得让日本团队变为完成，反之亦然。
