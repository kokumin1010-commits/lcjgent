# 給与明細独立密码保护设计

## 目标与边界

「給与明細」继续留在现有 `/master/finance?tab=cashflow` 页面，不新建页面。已登录员工在未完成二次验证前，只能看到带锁的給与入口；不得取得工资总额、逐人工资、员工姓名、工资月份、预算、预测、部门、实际汇率、异常、审计或工资银行证据。

| 层级 | 控制方式 |
|---|---|
| 前端 | 锁定前不挂载給与查询和控制台；給与表取込先要求解锁；提供明确的重新锁定操作 |
| 专用API | 給与照合、决策控制台、导入、修复、别名、预算、汇率、部门、异常状态全部要求給与解锁会话 |
| 共享现金流API | 未解锁时从列表、汇总、分类、余额趋势及CSV中排除工资/人工费记录；按ID编辑、删除、附件和审计操作先检查目标行是否属于給与 |
| 会话 | 正确密码后签发绑定当前用户ID的8小时HTTP-only签名cookie；退出或手动锁定时清除 |
| 密码 | 浏览器不保存密码；服务端只保存bcrypt摘要，验证过程不记录明文 |
| 防暴力尝试 | 按用户与IP限制连续失败次数；成功解锁后清除失败计数 |

## 給与记录定义

以下任一条件成立即视为受保护給与记录：`payrollRecordKey` 非空、`payrollMonth` 非空、`payrollEmployee` 非空，或 `category = '給与・人件費'`。因此工资表生成支出、已匹配银行工资、工资批量代发和人工费分析均受同一边界保护。

## 验收条件

未解锁时直接调用任何給与专用API应返回 `FORBIDDEN`；共享现金流接口不得返回受保护給与行。输入错误密码不得签发cookie；输入正确密码后才加载給与数据。手动锁定后清除cookie、給与查询缓存与工资筛选，并重新以隐藏工资的口径刷新共享现金流。
