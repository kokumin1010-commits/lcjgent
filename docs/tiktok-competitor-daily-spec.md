# 日本区TikTok竞争对手商品日报系统规范

## 目标与接入策略

系统嵌入现有「スタッフスケジュール」工作流。每天日本时间的早班运营进入日报任务，使用Kalodata日本市场数据确定店铺销量排名前5，并记录每店热卖前三商品，共15品。管理者查看全部运营的完成状态、数据对比和行动结论。

Kalodata接入采用双通道：**官方Open API优先，官方导出文件自动导入兜底**。当前未获得Open API认证格式与账号权限，因此第一版先交付可立即使用的导出导入功能；API未连接时明确显示“待连接”，禁止伪造或随机生成店铺、商品和指标。

## 排班与任务归属

每天的排名快照按市场和日期全局保存一次。系统从 `staff_schedules` 读取当天备注含 `[早班]`、且不是请假或休息的运营人员，并通过 `staff.email = users.email` 识别当前登录人。每位早班运营拥有独立日报，引用同一份当日排名快照，避免重复上传排名文件但保留个人巡查责任。

运营部门识别支持 `運営`、`运营`、`運營` 和 `operations`。管理员可以查看全部日报、重新指定人员、退回或确认；普通运营只能查看和编辑本人日报。若当天无有效早班运营，系统显示排班缺失，不自动把任意员工当作负责人。

## 数据结构

| 实体 | 核心字段 | 约束 |
|---|---|---|
| 排名快照 | 日期、市场、来源、原始文件证据、同步状态、查询条件 | 日期+市场+当前版本唯一 |
| 店铺排名 | 快照、店铺ID/名称/链接、排名、销量、销售额、增长率 | 自动选前5，允许额外观察店铺 |
| 运营日报 | 日期、负责人、状态、巡查时间、自动总结、提交/确认信息 | 日期+负责人唯一 |
| 商品巡查 | 日报、店铺、商品排名、名称/ID/链接、原价、直播价、销量、销售额、点击率、转化率、热度、截图 | 前5店每店恰好3个主商品 |
| 同步审计 | 来源、开始/结束时间、条件、成功/失败、行数、错误 | 不覆盖历史 |
| 操作审计 | 实体、动作、操作人、前后摘要、时间 | 保存、提交、退回、确认均记录 |

金额统一按JPY保存与显示。折扣率为 `(原价-直播成交价)/原价`，仅在原价与直播价均为有效非负值时计算。Kalodata销售额、销量等数据标记为市场情报估算，不用于结算或员工绩效。

## 导入规则

支持CSV/XLSX。系统通过中日英字段别名识别店铺排名与商品排名，优先读取工作表名或类型列；至少需要店铺名称、店铺排名或销量/销售额。若文件包含商品行，则按店铺内销量或销售额取前三；若仅有店铺榜单，则先生成前5店，商品字段由运营填写或继续导入商品榜单。

导入不会静默丢弃无法识别的行。预览必须显示识别结果、前5店、每店商品数、缺失字段和被排除行，运营确认后才写入。相同日期重复导入保存新版本并保留旧快照审计。

## 完整性与状态

日报状态为 `draft`、`submitted`、`returned`、`approved`。提交条件为5家主店铺、每店3个主商品、共15品；每品必须有商品名称、直播成交价、销量或热度证据、商品链接以及至少一张价格截图。点击率、销售额等Kalodata无数据时允许为空，但报告必须显示“无数据”，不能按0评价。

## 昨日对比与自动分析

同一商品优先以Kalodata商品ID匹配；无ID时使用规范化的店铺名+商品名匹配最近一个有数据的前日报。展示昨日与今日原价、直播价、折扣率、销量、销售额、点击率和转化率，以及绝对变化和变化率。

自动报告采用确定性指标模板，包含当日结论、前5店排名、15品完整率、最高销量/销售额商品、平均折扣、降价商品、点击率与转化率表现、价格变化、数据缺失、机会、风险和下一班次行动。无数据字段不参与平均值，也不生成猜测性结论。

## UI位置

「スタッフスケジュール」日视图增加“日本区TikTok竞品日报”任务卡，早班运营可进入本人日报，管理员可进入总览。日报使用独立路由承载15品表单和历史分析，避免继续扩大现有排班页面，但入口、身份和日期保持联动。
