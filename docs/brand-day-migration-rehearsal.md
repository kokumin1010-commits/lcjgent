# KGDAY → LCJ 原生迁移预演记录

## 清单与隐私控制

KGDAY 源数据通过沙箱外部脚本导出到 `/home/ubuntu/kgday_migration/kgday-manifest.json`，权限为 `0600`。清单不进入 Git，不作为构建产物，也不会在 LCJ 页面中显示个人资料或密码哈希。现有 bcrypt 哈希原样迁移，因此创作者不需要重设密码。

真实 LCJ Zod 与权限端点对完整清单执行了哈希和引用预检。结果为 `valid=true`，缺失截图URL、无效账号引用和无效商品引用均为0。42张对象存储原图均已从短时签名地址读取并重新计算 SHA-256；清单哈希保存在本地摘要中，不在文档回显任何对象地址或个人资料。

## 隔离数据库预演

本地建立独立 MariaDB `lcj_brandday_test`，应用 `0139_brand_day_native.sql` 后确认8张 `brand_day_*` 表全部创建。集成测试使用一套隔离记录和模拟对象存储执行以下流程：管理员预检、图片SHA-256核对、活动/报名/账号/成绩/商品/审计事务导入、来源ID映射、目标计数核对、同一 `migrationKey` 第二次执行幂等返回，以及测试数据清理。

首次预演发现 ISO 8601 字符串不能直接写入 MySQL/MariaDB `timestamp`。迁移端点已统一在写入前转换为 JavaScript `Date`，重跑后全部通过。完整 LCJ 构建同时保持 `DATABASE_URL` 未设置，确认不会再误连 KGDAY 数据库。

## 生产执行门槛

生产导入必须在 LCJ schema 发布完成后，由已登录管理员从「ブランドデー一覧」选择最新迁移清单。页面先显示六类计数并验证全部引用，再允许执行。执行时42张原图会下载、复核SHA-256并写入 LCJ R2；数据库事务完成后按来源ID统计26/26/42/81/164和42张原图。任何数量或哈希不一致都会将迁移批次标记为失败，且不得切换主数据源。
