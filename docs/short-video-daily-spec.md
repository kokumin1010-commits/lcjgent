# 短视频日报规格

## 目标

`/master/short-video?tab=daily`包含两个互不混算的事实分区：**账号每日GMV、订单数**与**视频互动次日快照**。运营人员原则上在第二天录入前一天数据；账号销售分区是积分和绩效的唯一订单/GMV来源，视频分区只用于观察内容互动。现有短视频矩阵、历史投稿和旧日报数据不迁移、不清零、不推测。

## 页面与权限

两个分区共享现有`/master/short-video`角色权限。查看需要`canView`或`canEdit`，新增、编辑、软删除需要`canEdit`；管理员保持既有旁路。制作人和绩效负责人只使用HR中当前在职、未归档、未合并的唯一员工记录，并保存`staffId + 姓名快照`。账号来源为现有未归档短视频账号，并保存`accountId + 账号名快照`。

## 分区一：账号每日GMV、订单数

每一行代表一个短视频账号在一个业务日期的后台整日销售。同一账号同一天只能存在一条有效记录，避免重复计入绩效。

| 字段           | 规则                                               |
| -------------- | -------------------------------------------------- |
| 数据日期       | 默认东京时间昨天；允许今天和过去日期，禁止未来日期 |
| 短视频账号     | 必填，来自现有未归档账号                           |
| 绩效负责人     | 必填，来自HR当前在职员工                           |
| 当日订单数     | 账号后台当日总订单，非负整数                       |
| 当日GMV        | 账号后台当日总GMV，非负、最多两位小数              |
| 币种           | JPY或CNY，分别汇总，不换算、不混加                 |
| 数据来源或备注 | 可选，最多2000字，可记录退款口径或后台来源         |

月度统计提供账号填报天数、月订单、JPY月GMV、CNY月GMV，并按日期、账号、绩效负责人拆分。后续积分或绩效只能读取`short_video_account_daily_sales`，不得读取单条视频的历史订单或GMV字段。

## 分区二：视频互动次日快照

一行对应一条可核验视频链接。当天发布条数由当日有效链接行数自动计算；一个日期可批量登记多条视频。

| 字段                                   | 规则                                               |
| -------------------------------------- | -------------------------------------------------- |
| 数据日期                               | 默认东京时间昨天；允许今天和过去日期，禁止未来日期 |
| 视频链接                               | 必填，必须是`http/https`，规范化后检查有效记录重复 |
| 发布账号                               | 可选，复用现有短视频账号                           |
| 制作人                                 | 必填，来自HR当前在职员工                           |
| 播放、点赞、评论、分享、收藏、商品点击 | 次日采集时的非负整数快照                           |
| 备注                                   | 可选，最多2000字                                   |

互动数为点赞、评论、分享、收藏之和；互动率为`互动数 / 播放量`；点击率为`商品点击 / 播放量`。这些数值会随时间变化，页面明确标注为次日快照。视频新建和编辑接口不再接受订单、GMV或币种。

## 历史兼容与零猜测

原`short_video_daily_entries`中的`orders`、`gmv`和`currency`列不删除、不清零、不迁移，因为无法证明旧视频行等于账号整日销售，也无法排除多视频重复归因。升级后视频月汇总不查询这些列，页面不展示这些旧销售值，新视频写入使用数据库默认0仅维持旧表兼容。

新`short_video_account_daily_sales`从空表开始，只接受员工依据真实账号后台填写的数据。软删除通过`activeKey=id`释放账号日唯一键，同时保留原记录与不可变审计日志。

## 数据库与审计

Railway MySQL新增`short_video_account_daily_sales`与`short_video_account_daily_sales_audit_logs`。数据库v2升级在服务监听前执行，包含独立迁移前/后加密备份、幂等建表、结构健康检查，以及视频表和账号销售表的迁移前后业务指纹核对。建表过程业务写入为0，旧TiDB不得连接、读取或恢复。
