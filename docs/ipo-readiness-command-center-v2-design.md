# LCJ 上场准备综合司令塔 V2 设计

## 1. 目标与边界

本升级把现有“目标—正式营业利润—现金参考”页面扩展为可执行的上场项目管理工具。保持以下不可突破的边界：

1. **正式完成率**只使用 `finance_monthly_pnl.status IN ('closed','audited')` 的营业利润。
2. **银行经营现金**仅作管理参考，排除本社送金与账户间转账，不写入正式P/L。
3. **计划与预测**必须标记为计划／估算／敏感度，不表述为已实现业绩或上市保证。
4. 没有来源的数据保持空白或“待设置”，不生成公司特有的销售、毛利、负责人、期限或审计结论。
5. 所有读取与写入沿用现有 `financeProcedure` 二次财务认证；写入保留操作者、时间和前后快照。

## 2. 新增能力

| 模块 | 数据来源 | 主要结果 |
|---|---|---|
| 月度目标趋势 | 公司阶段目标平均分配＋可选月度覆盖；正式P/L；银行现金参考 | 月目标、正式实绩、现金参考、累计差额 |
| 目标差额反推 | 剩余营业利润目标＋用户设置的目标营业利润率 | 所需剩余销售额、月均销售额；无利润率时显示待设置 |
| 三情景预测 | 已月结平均营业利润；无正式数据时另列现金参考敏感度 | Downside 80%、Base 100%、Upside 120%，明确是敏感度而非承诺 |
| 利润驱动拆解 | 正式P/L的销售、毛利、营业利润 | 売上原价＝销售－毛利；营业费用＝毛利－营业利润；毛利率／营业利润率 |
| 现金支出驱动 | 现有银行流水分类汇总 | 经营现金出金Top分类；与正式P/L分区显示 |
| 月结质量 | 月份、P/L状态、更新时间、预期月结月份 | 未登记／草稿／月结／审计、缺口月份、数据时效 |
| 上场准备清单 | 新任务表 | 财务审计、内部控制、治理、法务披露、信息系统、资本市场六领域进度 |
| 审计证据完整率 | 清单任务的证据URL | 完成率、证据覆盖率、逾期与阻塞项 |
| 董事会月报 | 当前正式业绩、现金参考、预测、任务快照 | 版本化保存、历史查看、打印／另存PDF |

## 3. 新增数据表

### `ipo_monthly_plans`

每月一行，可覆盖阶段目标的平均分配。字段：`month`、`revenueTargetJpy`、`grossProfitTargetJpy`、`operatingProfitTargetJpy`、`note`、操作者、时间。不存在覆盖行时，营业利润目标按当前阶段总目标／阶段月数均匀分配；销售与毛利目标不推测。

### `ipo_readiness_settings`

单例设置，保存可审计的模型假设：`targetOperatingMarginPct`、`downsideFactor`、`baseFactor`、`upsideFactor`、`monthlyCloseDueDay`、操作者与时间。情景默认只作为当前run-rate的80%／100%／120%敏感度；目标营业利润率没有明确设置时，不反推销售额。

### `ipo_readiness_tasks`

字段：`workstream`、`title`、`description`、`ownerName`、`priority`、`status`、`progress`、`dueDate`、`evidenceJson`、`blocker`、`completedAt`、软删除、操作者与时间。任务不自动标记完成；证据URL只用于追踪，不代表审计认可。

### `ipo_board_report_snapshots`

字段：`seriesKey`、`asOfMonth`、`versionNumber`、`title`、`status`、`summaryJson`、`createdBy`、`createdAt`。每次生成保存当时的正式业绩、现金参考、差额、预测与任务状态，不随未来数据变化。

### `ipo_readiness_audit_logs`

保存月度计划、设置、任务、董事会报告的新增／更新／归档前后JSON与操作者。日志中不保存财务二次密码或工资个人明细。

## 4. 默认清单策略

首次建表只插入通用模板任务，全部为 `todo`、负责人和期限为空，不代表LCJ已经完成或缺失具体审计事项。模板覆盖：月结与会计方针、监查法人、银行勾稽、存货／应收／应付、关联方交易、董事会与规程、内部通报、权限管理、合同与风险披露、资本政策与股权结构、适时披露体制。

## 5. API与权限

`cashflow.getFinanceCommandCenter`继续返回现有IPO模型，并新增 `ipoOperations`。新增mutation：保存月度计划、保存模型设置、新增／更新／归档任务、生成董事会快照。全部使用 `financeProcedure`；输入用Zod限制长度、枚举、百分比、URL和日期。每次mutation写活动日志与IPO审计日志。

## 6. UI结构

1. 现有标题与四张核心KPI保持。
2. 新增“月度目标／正式实绩／现金参考”趋势图。
3. 新增“目标差额反推＋三情景预测”双栏。
4. 新增“正式P/L利润桥＋银行现金支出Top分类”双栏。
5. 新增“月结质量日历”。
6. 新增“上场准备清单”，可筛选领域、状态和优先级，并编辑负责人、期限、进度、阻塞原因和证据链接。
7. 新增“董事会月报”，可生成版本、查看历史并打印。

## 7. 部署安全

新增表使用 `CREATE TABLE IF NOT EXISTS` 的非破坏性升级；不修改、删除或回填现有财务业务行。提交前执行定向Vitest、esbuild和 `git diff --check`。推送GitHub后等待Railway状态成功，验证页面HTTP 200、未认证财务API 401、生产资源包含新文案，并确认仓库clean。

## 8. 官方依据

截至2026-09-12，本设计参考以下JPX官方资料：

1. 上場審査基準概要（グロース市場）：https://www.jpx.co.jp/equities/listing/criteria/listing/02.html 。其中列明企业及风险信息披露、经营健全性、公司治理与内部管理体制有效性、事业计划合理性等审查维度。
2. 新規上場の検討にあたって：https://www.jpx.co.jp/equities/listing-on-tse/ipo-benefits/03.html 。其中说明上场后的适时适当披露、规范遵守、企业价值提升，以及准备阶段的役员／役职员教育、不祥事预防和内部管理体制建设。

当前目标市场尚未由用户确定，因此本系统不写入Growth、Standard或Prime任一市场的形式要件阈值；清单只采用各市场共通的准备维度。
