# 选品中心父子SKU展示与编辑实施规格

## 目标与边界

本修复只修改`/master/selection-center?tab=products`的商品父子SKU展示和保存链路。Railway MySQL继续是唯一生产数据库；不连接旧TiDB，不创建测试商品，不批量转换或猜测现有SKU业务数据，不修改拍卖、套组、HR、财务、早会或其他标签功能。

## 两种既有SKU模型

系统当前同时存在两种有效模型。第一种是`selection_products`中的实体子行，以`parentProductId`关联父商品；生产有10条，KG恢复来源键保存在隐藏的`productId`，可编辑SKU编号保存在`skuName`。第二种是父商品`skuVariants` JSON数组；生产有22条，当前只有名称、定价、最低价、折扣和促销。两种模型当前无身份重叠。

本次不建立新表，也不把JSON变体擅自转换为实体行。列表层把两种来源统一为独立子SKU行，编辑层分别调用专用事务过程，保持所有既有引用和恢复语义。

## 列表展示

父商品行保留图片、名称/中文名/TikTok商品ID、品牌、分类、价格、历史最低、保护期、佣金、库存、状态、套组和操作。状态与套组列必须严格按表头顺序，不再错位。

父商品的展开计数为实体子SKU与JSON变体的合计。展开后，每个SKU各占一行并包含：父图或子图、缩进层级、SKU显示名称、来源标记、SKU编号、品牌、分类、定价、历史最低/最低价、保护期或明确占位、佣金或明确占位、独立库存、独立状态、促销/套组标记与操作按钮。

JSON变体不再额外显示为父行下方的压缩胶囊，避免重复。实体子SKU使用自己的图片、名称和字段；JSON变体继承父商品图片、品牌和分类，仅作展示继承，不把继承值写回JSON。

损坏的图片JSON或SKU JSON必须安全回退并显示错误提示，不能让整张商品表白屏。

## SKU字段与兼容规则

`SelectionProductSkuVariant`扩展为以下可选字段：`variantId`、`skuCode`、`stock`、`status`。原有`name`、`price`、`lowestPrice`、`discountRate`和`promotionType`保持兼容。`status`只允许`draft`、`online`或`offline`；库存为0以上整数；SKU编号最长100字；`variantId`为服务端生成的稳定UUID。

旧JSON变体没有`variantId`、库存或状态时，列表只做安全展示：库存显示0，状态暂按父商品状态展示，但不在只读加载时写回。第一次专用编辑保存时，服务端为目标变体补稳定`variantId`并保存用户确认后的库存/状态。

同一父商品内SKU名称继续按NFKC、折叠空白和不区分大小写去重；SKU编号非空时也必须唯一。完全空白的新SKU行仍被过滤。现有1+1、1+2、1+4等促销字符串继续逐SKU保存。

## 实体子SKU编辑

实体子SKU使用专用弹窗和`updateChildProductSku`受保护procedure。可编辑字段为：子SKU显示名称、SKU编号（映射`skuName`）、条码、定价、历史最低价、库存、状态、促销组合和图片。隐藏的KG恢复`productId`来源键、`parentProductId`、`brandId`默认不可编辑，避免破坏恢复身份与父级关系。

服务端事务必须`SELECT ... FOR UPDATE`并验证目标仍是指定父商品的未删除子行。UPDATE使用固定白名单，检查`affectedRows=1`；历史最低价沿用现有价格历史语义，新增证据只允许使历史最低保持或降低。失败必须rollback。

## JSON变体编辑

JSON变体使用专用弹窗和`updateEmbeddedProductSku`受保护procedure。输入包含父商品ID、`variantId`（若已有）、回退索引和预期原始身份，以及允许修改的SKU字段。服务端锁定父商品行、重新读取并规范化整个`skuVariants`，按稳定ID定位；旧数据首次修改时只在索引和预期身份均匹配的情况下定位，防止并发覆盖错误SKU。

补丁应用后重新校验全数组名称/编号唯一性、数字范围和促销长度，保存JSON并同步第一条SKU的legacy列。第二次、第三次编辑使用持久化`variantId`定位；目标不存在或身份已变化时返回冲突提示，不静默覆盖。

删除JSON变体通过同一父行锁与稳定身份规则执行，不允许依赖前端旧数组覆盖。实体子SKU解除父级继续保留，但改为受保护事务、存在检查、affectedRows确认和明确错误提示。

## 验证要求

单元/事务测试必须覆盖：10条实体子SKU模型、旧JSON变体升级、SKU编号和名称重复拒绝、价格/库存/状态/促销保存、第一次与连续第二/第三次修改、并发身份冲突、目标不存在、affectedRows异常和rollback。

纯mock Chromium必须覆盖：父商品展开后两种SKU均为独立行；编辑实体子SKU两次；编辑JSON变体三次；新增SKU经父商品表单后成为独立行；状态/库存/编号/1+1组合刷新和重新登录保持；删除和错误提示不造成半套数据。生产只做读取、展开、打开弹窗和本地不保存修改，所有mutation拦截，记录前后计数不变。
