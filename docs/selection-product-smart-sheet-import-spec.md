# 选品中心商品表智能识别与导入规格

## 目标

在选品中心的「商品管理」操作栏保留现有单张商品图片AI识别，并新增独立的「表格识别」入口。用户选择CSV、XLSX或XLS后，服务器进行确定性的智能表头匹配，先返回预览；只有用户勾选商品、补齐必要品牌并再次确认后，才以单一事务写入Railway MySQL。识别过程不调用LLM，因此不产生按文件或按行的AI额度费用。

## 真实Kalodata样本基线

用户提供的Kalodata真实样本工作簿包含`LIST_PRODUCT`和`Intro`两个工作表。可导入表有200条数据、20列；200条均可从Kalodata详情页或TikTok链接提取TikTok商品ID，且样本内没有重复商品ID或重复商品名。商品名最长129字符，符合现有255字符业务校验。

| 样本字段情况 | 数量或结论 | 导入语义 |
|---|---:|---|
| 商品名称、图片、分类、价格、运费、佣金、TikTok链接 | 200行均存在 | 只导入有直接证据的值 |
| 单一价格 | 179行 | 作为商品价格候选 |
| 价格区间 | 21行 | 不选择最低/最高值；商品价格留空并显示警告 |
| TikTok商品ID | 200行 | 从受信任HTTP(S)商品URL确定性提取 |
| 品牌列 | 无 | 不从商品名猜品牌；用户在预览中统一或逐行指定 |
| SKU、条码、库存列 | 无 | 不生成虚假SKU/条码；新商品以草稿和库存0保存，并明确标注“源文件未提供库存” |
| 销量、GMV、评分、达人等分析列 | 有 | 仅在预览中作为来源参考，不冒充商品主档字段 |

## 字段映射

| 表格字段别名 | 商品字段 | 规则 |
|---|---|---|
| 商品名称、商品名、製品名、Product Name | `productName` | 必填，去除首尾空白，不翻译、不重写，最大255字符 |
| TikTok链接、TikTok URL、商品链接 | `productLink` | 仅允许HTTP(S)，优先TikTok商品链接 |
| Kalodata详情页链接 | TikTok商品ID辅助来源 | 仅用于提取数字ID与预览来源，不写入永久公开凭据 |
| 图片链接、画像URL | `images[0]` | 仅允许HTTP(S) |
| 类目、カテゴリ、Category | 分类候选 | 对现有分类名称或中文名称做标准化精确匹配；不能匹配则保持空白 |
| 价格(円)、価格、Price | `price` | 仅接受单一非负安全数值；区间、文本或异常值留空 |
| 运费(円)、送料 | `shippingFee` | 单一非负安全数值 |
| 佣金比例、コミッション率 | `commissionType=percentage`、`commissionValue` | 仅接受0至100的百分比 |
| 商品ID、Product ID、TikTok链接中的ID | `productId` | 仅接受数字/安全短字符串；TikTok链接的数字ID可确定性提取 |

## 安全限制

文件上限为10MB，最多2000条数据。XLSX必须有ZIP签名，XLS必须有OLE签名，CSV不得含NUL字节。只读取第一个能匹配“商品名称”表头且包含数据的工作表；说明页和未知工作表不导入。所有URL只允许`http:`或`https:`。价格、运费和佣金必须是有限安全数值；任何缺失、区间或异常值都保持空白，不以0代替证据。

预览时服务器查询当前未删除商品，以`productId`为第一去重键、标准化商品名加品牌为第二去重键。已存在商品默认不可选，提交时在事务内再次检查，防止预览后并发创建造成重复。品牌缺失的选中行禁止提交。源文件没有SKU时，不创建任何SKU变体。

## 提交与兼容

客户端提交原文件、服务器预览摘要和用户选择的来源行号/品牌修正。服务器重新解析原文件，不信任客户端改写的商品名、价格、图片、链接或佣金，并在单一数据库事务中插入所有仍可导入的选中行；任一插入失败则整批回滚。所有商品均以`draft`创建，不自动上架，不覆盖现有165件商品，不修改价格历史、库存或SKU。

现有图片「AI识别」功能继续使用原按钮和原接口。新入口明确标注「表格识别（無料）」；表格解析不调用`invokeLLM`。CSV输出、手工添加、编辑、子SKU和历史最低价功能保持不变。
