# 短视频日报规格

## 目标

在现有“短视频运营部”中新增“短视频日报 / 短動画日報”入口。运营人员原则上在第二天登记前一天发布的视频，每条视频保存可核验链接、制作人、互动、转化和GMV；系统自动形成每日和每月汇总。现有短视频矩阵及其 `svm_video_posts` 数据不迁移、不改写，也不伪造历史日报。

## 页面与权限

日报使用现有路由 `/master/short-video?tab=daily`，与短视频矩阵共享 `/master/short-video` 的角色权限。查看需要 `canView` 或 `canEdit`，新增、编辑、删除需要 `canEdit`；管理员保持完整权限。制作人来源只使用HR中当前在职、未归档、未合并的唯一员工记录，并保存 `staffId + 姓名快照`，因此员工姓名变化不会破坏历史证据。

## 录入模型

每一行代表一个已发布短视频，因此“当天发布条数”由当日有效链接行数自动计算，不允许人工填写一个与链接数量不一致的总数。一个日期可批量登记多条视频。

| 字段                         | 规则                                                                                                       |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 数据日期                     | 默认东京时区的昨天；允许补录今天及过去日期，禁止未来日期。                                                 |
| 视频链接                     | 必填，必须是 `http/https`；规范化后检查当前有效记录重复。                                                  |
| 发布账号                     | 可选，复用现有短视频矩阵账号并保存账号名快照。                                                             |
| 制作人                       | 必填，来自HR当前在职员工；保存员工ID和姓名快照。                                                           |
| 播放、点赞、评论、分享、收藏 | 非负整数，默认0。                                                                                          |
| 商品点击                     | 非负整数，默认0。                                                                                          |
| 成交订单                     | 非负整数，默认0，且不得高于商品点击；若点击为0但有成交，可作为平台未提供点击数据的例外保存并显示口径提示。 |
| GMV                          | 非负金额，保留两位小数；币种为JPY或CNY，不将两种币种无依据相加。                                           |
| 备注                         | 可选，最多2000字。                                                                                         |

## 指标口径

互动数为点赞、评论、分享、收藏之和。互动率为 `互动数 / 播放量 × 100%`。点击率为 `商品点击 / 播放量 × 100%`。点击成交转化率为 `成交订单 / 商品点击 × 100%`；商品点击为0时不显示该转化率，不使用播放量代替点击量。播放成交率另行显示为 `成交订单 / 播放量 × 100%`。

月度汇总按所选月份和币种分别计算发布条数、活跃天数、制作人数、播放、互动、点击、订单和GMV，并提供按日期、按制作人的拆分。没有记录的月份明确显示0，不生成假数据。

## 数据安全

新增独立的 `short_video_daily_entries` 和 `short_video_daily_audit_logs` 表，避免改变现有短视频矩阵记录语义。业务记录采用软删除；新增、编辑、删除都写入不可变审计日志。数据库升级在服务监听前执行，必须通过Railway MySQL加密备份门控、幂等建表、结构健康检查和迁移前后业务行指纹核对。旧TiDB不得连接、读取或恢复。
