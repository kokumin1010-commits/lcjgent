# 拍卖每SKU与组合登记实施规格

## 目标与边界

本修复仅扩展`/master/selection-center?tab=auction`的Excel预检、拍卖轮次编辑和商品SKU选择，并对商品编辑中的每SKU促销输入做兼容增强。拍卖记录仍保存于Railway MySQL的`auction_records`，每轮SKU/组合继续放在现有`roundsJson`中；不新增平行SKU表，不迁移、重写或推测现有6条拍卖记录和10个轮次，不触碰套组管理、HR、财务、早会、店铺等模块。

## 每SKU拍卖模型

每个拍卖轮次代表一次实际拍卖。轮次保留`roundNumber`、起拍价、成交价、竞拍人数、获胜者、开始时间、时长，并包含`skuName`、`skuId`和新增的`promotionType`。`promotionType`为空表示单品/无组合；非空值必须是`正整数+正整数`，例如`1+1`、`1+2`、`1+4`、`10+1`。旧轮次缺少该字段时按空值读取，不改写原数据。

同一SKU可以出现在多个轮次，因此“第二次”及后续登记不会被去重。编辑器提供三条路径：新增空轮次；把当前轮次的SKU与组合复制为下一次登记（价格结果等实际拍卖字段重置）；把匹配商品的所有选品SKU一次加入为待登记轮次。用户仍可手工输入未知SKU，不强制猜测SKU ID。

商品SKU候选从现有`selection_products.skuVariants`、legacy单SKU字段和子SKU行只读派生。组合优先使用SKU的`promotionType`；若旧恢复数据把`1+1`等组合写在SKU名称中，则只提取明确的数字加号数字形式作为显示候选。SKU名称、ID和组合仍以用户在拍卖轮次中最终保存的快照为准，不反向改写商品主数据。

## Excel兼容

解析器扫描前30行寻找真实表头，不再固定第1行。核心要求仅为可确认的商品身份（商品ID或PID）和成交价；商品名、库存、销售数、GMV、SKU名、SKU ID、起拍价、获胜者、竞拍人数、开始时间、时长均允许缺少并使用安全空值。SKU名与SKU ID至少有一个时保留SKU身份；两者都缺少时仍可保留商品级拍卖轮次，但预检明确统计无SKU轮次。

扩大TikTok中日英表头别名，同时保留已经验证的14列标准格式。若没有找到足够可靠的表头，不盲目按任意位置导入，而是显示检测到的前几列表头与缺失核心列。预检显示商品数、唯一SKU数、拍卖轮次数、表头行、原始行与跳过行。后端继续验证扩展名、MIME、base64、大小、SHA-256、文件签名和实际工作簿可解析性。

## 保存与重复编辑

前端每次保存前调用共享canonical规范化；后端对`promotionType`、SKU名称/ID、价格与轮次编号重新验证。`update`继续使用`SELECT ... FOR UPDATE`、固定列白名单、`affectedRows=1`和单一MySQL transaction。测试必须连续更新同一记录至少两次，并在每次重新读取/重新打开后确认第二次和第三次保存覆盖的是当前值，且其他SKU轮次未丢失。

## 验收

必须覆盖：标题行偏移；中文/英文别名；缺少非关键列仍导入；缺少核心商品身份或成交价明确拒绝；一个商品多SKU；同一SKU两次拍卖；`1+1`、`1+2`和`1+4`；商品SKU全部加入；每轮手工修改；第二次和第三次编辑；刷新及新登录保持；错误时无部分写入。所有浏览器数据使用本地mock，生产验收只打开和编辑前端状态、选择本地文件预检，不点击上传或保存。
