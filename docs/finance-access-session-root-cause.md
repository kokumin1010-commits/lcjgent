# 财务二次验证8小时会话失效根因

## 根因

财务解锁Cookie本身保存8小时，但JWT同时绑定前端发送的 `X-LCJ-Finance-Session`。该会话ID仅保存在JavaScript模块内存，并且 `FinanceManagement` 组件卸载时会主动执行 `clearFinanceAccessSession()`。

因此，只要刷新页面、重新载入前端资源、离开财务页后重新进入，或组件因路由切换重新挂载，前端就会生成新的会话ID。服务器收到的Cookie仍绑定旧ID，状态检查因ID不一致返回未解锁，导致用户在8小时内反复输入密码。

## 安全修复边界

会话ID应保存到同源浏览器存储，保存期限与服务器返回的财务Cookie到期时间一致。刷新、财务标签切换和重新打开财务网址时复用同一ID。组件普通卸载不清除；只有手动“锁定财务”、主账号退出、存储过期或显式安全失效时才清除。服务器仍同时校验当前登录用户ID、HttpOnly签名Cookie、会话ID和JWT到期时间。
