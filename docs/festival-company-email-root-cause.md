# Live Commerce Festival 企业报名邮件根因

## 当前行为

企业报名成功后会创建Festival账号和入场票，并尝试发送一封带二维码的“入场チケット”邮件。报名成功页另行承诺“担当者より3営業日以内にご連絡いたします”。

## 根因

1. `sendTicketEmail` 直接创建单一SMTP连接，只读取 `EMAIL_USER/EMAIL_PASSWORD`，绕过项目已有的主邮件服务与Gmail故障切换。
2. 邮件发送只返回布尔值；企业报名邮件没有写入可追踪日志，因此后台无法区分未触发、SMTP拒绝、已接受或重复提交。
3. 现有Festival邮件审计表仅允许密码重置／密码变更，无法表达报名受理、门票或审核联络。
4. 企业重复提交时，如果门票已经存在，代码不会再次尝试邮件；返回值却默认为发送失败，用户无法补救。
5. 当前门票邮件只说明入场二维码，没有清楚说明报名已受理、3个工作日内会收到什么、未收到时如何联系。
6. “3个工作日”是人工联络承诺，当前没有自动审核结果邮件或超时追踪链。

## 安全修复边界

未来新报名必须使用统一主／备用邮件服务，先按申请ID和用途做幂等检查，再发送一封合并的“报名受理＋入场二维码＋后续流程”邮件，并记录收件人SHA-256、域名、状态、提供商、消息ID和安全错误码。不得保存完整收件地址到审计日志。

现有报名不自动群发。只有后台明确选择单个申请并确认补发时才能发送。工资、密码等既有邮件行为不因本修复改变。

## 本番页面证据（2026-08-31）

官网入口：[Live Commerce Festival](https://www.livecommercefestival.com/)；企业报名页：[企業出展・協賛 お申し込み](https://www.livecommercefestival.com/livecommercefestival/2026/apply/company)。公开页面实际为17步企业报名表。成功界面当前显示“企業出展のお申し込みを受け付けました。担当者より3営業日以内にご連絡いたします”，门票区仅根据 `ticketEmailSent` 显示“メールにもQRコードを送信しました”或“メール送信を確認できませんでした”。它没有独立显示报名受理邮件状态，也没有说明3个工作日内会收到哪类联络。

短期本番零发送审计确认：Aliyun与Gmail两个SMTP配置均存在且认证检查成功；2026企业报名24件、企业门票24件、缺票0件、重复报名组0件。现有企业门票发送路径仍未使用主／备用故障切换、未写发送审计、无幂等补发、无3个工作日跟踪。现有Festival邮件审计仅包含密码重置已接受15件、密码变更已接受12件；审计未发送任何邮件且未返回个人信息。
