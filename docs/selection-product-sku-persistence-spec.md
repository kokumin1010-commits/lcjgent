# 選品中心 商品名称・タグ・SKU保存修正仕様

## 目的

`/master/selection-center?tab=products` の**新規商品**と**既存商品**について、商品名・中文名・タグ・複数SKUの追加、編集、削除を一度の保存で確実に反映する。保存先は既存の `selection_products` とし、旧Manus TiDB、MALL用 `mall_product_variants`、KG復元処理、他モジュールには接続・変更しない。

## 確認済み根因

| 項目 | 現状の問題 | 修正方針 |
|---|---|---|
| タグ | 既存データの `tags` がJSON文字列のままフォームに入り、更新時に文字列を送信するため、配列を要求するZod検証で更新全体が拒否される | フォーム初期化と送信直前に配列へ正規化し、サーバー境界でも配列・JSON文字列・単一文字列を互換受理する |
| 既存SKU | `skuVariants` がJSON文字列の場合、文字列の `.length` は通るが配列として編集・送信できない | フォームを開く時点で必ず配列へ正規化する |
| 新規SKU | `createProduct` が `skuVariants` と関連SKU列を入力・INSERT対象に含めていない | 新規作成schemaとINSERTへ追加し、更新と同じ正規化済みSKUを保存する |
| SKU削除 | 最後の1行には削除ボタンが出ず、更新時に空配列も送られない | 1行だけでも削除可能にし、空配列を明示送信して既存SKUを消せるようにする |
| 原子性 | 商品本体と価格・割引履歴が別々に書かれ、途中失敗時に一部だけ残る可能性がある | 商品本体と履歴を同一MySQL transactionでcommit/rollbackする |

## 正規化・検証ルール

タグは前後空白を除去し、空文字を削除し、同一文字列を重複排除する。上限は30件、1件100文字とする。JSON配列文字列、配列、単一文字列を互換入力として扱い、保存時は常に配列のJSONへ統一する。

SKUは既存UIが扱う `name`、`price`、`lowestPrice`、`discountRate`、`promotionType` を正規化する。完全な空行は保存対象から除外する。一部入力された行は名称を必須とし、価格系は有限かつ0以上、割引率は0以上100以下とする。SKU名称はUnicode NFKC、連続空白の統合、小文字化で比較し、重複時は保存を拒否して行番号付きエラーを表示する。SKUコード項目は現行データ根拠がないため新設せず、既存の「名称」フィールドをSKU識別子として扱う。

既存の単一SKU列 `skuName`、`skuPrice`、`skuLowestPrice`、`skuDiscountRate` は互換のため維持する。既存商品に `skuVariants` がなく単一SKU列だけある場合、フォームでは1行のSKUへ変換する。保存時は正規化済みSKU配列の先頭行を単一SKU列にも同期し、全SKU削除時は単一SKU列も明示的に `NULL` へ更新する。

## 保存境界

| 操作 | transaction内の処理 | 失敗時 |
|---|---|---|
| 新規作成 | 商品INSERT、必要な価格履歴INSERT、必要な割引履歴INSERT | 全件rollbackし、商品もSKUも残さない |
| 既存更新 | 対象商品を `FOR UPDATE` で存在確認、許可列のみUPDATE、必要な履歴INSERT、履歴最小/最大値を商品へ反映 | 全件rollbackし、更新前状態を維持する |

更新対象が存在しない、または論理削除済みの場合は `NOT_FOUND` とする。SQL列名は固定ホワイトリストから生成し、更新件数が1件であることを確認する。列追加DDLはtransaction外の一度だけのschema ensureへ集約し、毎回の保存中に実行しない。

## 画面動作

商品フォームを開いた時点で `images`、`detailImages`、`videos`、`exclusiveLiverIds`、`tags`、`skuVariants` を安全に配列化する。商品名と中文名は正規化されたタグ・SKUと同じpayloadで送るため、タグ型エラーによる巻き添え失敗をなくす。保存ボタンは商品名とブランドを満たす時のみ有効とし、SKU検証エラーは保存APIを呼ぶ前にtoastで明示する。サーバーでも同じ規則を再検証し、改変リクエストを拒否する。

## 回帰条件

モックデータのみを用い、新規商品で複数SKUが作成payloadとINSERTへ入ること、既存のJSON文字列タグを持つ商品で商品名・中文名・SKUを同時更新できること、SKU追加・編集・最後の1行を含む削除が再取得後も一致すること、重複SKU・不正数値・途中SQL失敗で書込みがcommitされないことを確認する。本番では商品/SKUの作成・更新テストを行わず、認証済み画面と読取API、デプロイ、バックアップ健全性のみを確認する。
